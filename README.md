# Lichess Analys

Веб-интерфейс для просмотра, фильтрации и локального анализа партий пользователя Lichess.

## Стек

- TypeScript и React 19
- Vinext (совместимый с Next.js App Router) поверх Vite
- локальные PGN-файлы, без API, токена и базы данных
- Stockfish 18 Lite в браузере через WebAssembly

## Настройка

Приложение находится в папке `web`. Скопируйте `web/.env.example` в
`web/.env.local` и замените значение `LICHESS_USERNAME` на свой логин Lichess.

История партий собирается из всех файлов с расширением `.pgn` в папке `pgn`
в корне проекта. Имена файлов могут быть любыми. Чтобы добавить новые партии,
положите туда очередной экспорт; повторяющиеся партии будут объединены по ID.
PGN-файлы загружаются и обрабатываются непосредственно в браузере — отдельного
API или серверного слоя для списка партий нет.

## Анализ партий

Просмотрщик использует готовые оценки `[%eval ...]`, если они присутствуют в
PGN, и показывает шкалу позиции, график партии и ошибки пользователя. Для любой
позиции можно запустить Stockfish в браузере, увидеть лучший вариант или
проанализировать всю партию. Результаты полного анализа сохраняются локально в
IndexedDB и повторно не вычисляются на этом устройстве.

Для предварительного анализа всей коллекции есть возобновляемый пакетный
скрипт. Он запускает несколько процессов Stockfish, сохраняет каждую готовую
партию отдельным JSON-файлом и при следующем запуске пропускает уже актуальные
результаты. Файлы появляются в
`web/public/analysis/stockfish-18-lite-depth-18`, после чего просмотрщик
автоматически использует их вместо повторного вычисления в браузере.

```bash
cd web
npm run analyze:pgn -- --dry-run
npm run analyze:pgn
```

Первой командой можно оценить оставшийся объём работы. Доступные параметры,
включая число процессов, другую папку PGN и принудительный пересчёт, описаны в
`npm run analyze:pgn -- --help`.

В приложение включена сборка [Stockfish.js](https://github.com/nmrugg/stockfish.js),
распространяемая по лицензии GPLv3. Анализ выполняется локально: позиции не
отправляются сторонним сервисам.

На главной странице собраны проигранные дебюты по типам ошибок. Дебютная ошибка
ищется до 10-го хода включительно, если ещё не наступил эндшпиль. С 11-го по
15-й ход включительно дебют продолжается, пока хотя бы одна сторона не завершила
развитие: минимум 3 из 4 исходных лёгких фигур выведены или разменяны и выполнена
рокировка. История ходов учитывается: возвращение фигуры на исходное поле не
отменяет её развитие. После 15-го хода или перехода в эндшпиль дебют окончен.
Стадия определяется по позиции перед ошибкой; сам ход, завершивший дебют,
может попасть в подборку. Завершившийся дебют больше не начинается заново.
Для дебютов и эндшпилей действует общий критерий: до хода оценка за игрока
не ниже −0.50, после — не выше −2.00. Дальше оценка не должна подниматься выше
значения сразу после ошибки до конца партии или первого серьёзного зевка
соперника (потеря от 3 пешек по оценке). Улучшение до такого зевка исключает ход.
Результат партии сам по себе не исключает ошибку: учитываются в том числе
победы по времени и после зевка соперника. Явно выбранный фильтр результата
продолжает действовать. Для каждой стороны берётся первый подходящий ход
в каждой фазе. Дебютные ошибки группируются по предполагаемым причинам:
потеря материала, угрозы королю, отставание в развитии, ослабление пешечной
структуры и прочие ошибки. Это эвристические признаки, а не объяснения от движка:
потеря материала и повторные шахи ищутся в первых 8 полуходах сохранённой линии
после ошибки (незавершённая пара ходов отбрасывается); мат — по оценке Stockfish.
Отставание в развитии отмечается, когда игрок отстаёт по развитию исходных
лёгких фигур или рокировке, но вместо рекомендованного развития делает другой ход.
Пешечная группа требует появления дополнительной сдвоенности или изоляции
относительно позиции до ошибки и позиции после рекомендованного хода.
В карточке показаны конкретный признак, оценки до и после, сыгранный и лучший
ходы. Одна партия может входить в несколько групп; общий счётчик считает её
один раз. Самые частые группы идут первыми, внутри каждой — страницы по 3 партии.
Для обновления групп из уже сохранённого анализа: `cd web && npm run statistics`.
Повторный анализ Stockfish не требуется.
Эндшпили группируются по материалу и структуре: пешечные окончания на одном,
двух или разных флангах, ладейные с одной или двумя ладьями, слоновые, коневые,
ферзевые и смешанные окончания. Ссылки из аналитических подборок открывают
партию в новой вкладке сразу на найденном критическом ходе.
Блок анализа и список партий используют общий фильтр периода, контроля и
результата. Компактная панель фильтров закрепляется в верхней части экрана при
прокрутке, а выбранные фильтры сохраняются в браузере. На главной одновременно
показывается только один выбранный раздел: все партии, резюме периода,
проигранные дебюты или решающие ошибки в эндшпиле. Индекс анализа автоматически обновляется перед
запуском приложения и production-сборкой.

## Резюме периода

Раздел «Резюме периода» использует общие фильтры и формирует локальный план
работы по сохранённому анализу. Внешняя языковая модель и повторный расчёт
Stockfish не нужны. Новые показатели добавляются при обновлении индекса
`npm run statistics` (также автоматически перед обычным запуском и сборкой).
Требуется индекс версии 14; при старом индексе интерфейс предлагает перезапуск.

В резюме показаны:

- покрытие полным анализом относительно выбранных завершённых партий из PGN;
- подтверждённые сильные стороны и повторяющиеся слабости с примерами;
- до трёх приоритетов на неделю: причина выбора, упражнение и показатель прогресса;
- подборки по три позиции из разных партий, с доской перед вашим ходом,
  скрытым решением и ссылкой в просмотрщик;
- динамика относительно непосредственно предшествующего периода той же
  длительности, отдельно для каждого точного контроля времени;
- все показатели с числителями, знаменателями и критериями отбора.

Оценки всегда приводятся со стороны игрока. Дебютный выход учитывается только
при состоявшемся переходе к следующей стадии: успех — от +0.50, проблема —
ниже −0.50. Реализация — победа после позиции от +2.00 перед своим ходом,
если оценка затем ни разу не опускалась ниже +1.00. Упущенное преимущество —
собственный ход, пересекающий +1.00 вниз после такого преимущества; последующая
победа не отменяет этот эпизод.

Возможности после ошибок соперника учитываются, если он потерял от 1.50 и
перед ответом оценка игрока находится между −0.50 и +5.00. Успешный ответ
теряет не более 0.50, неудачный — от 1.00. Удержание равного окончания требует
начальной оценки от −0.50 до +0.50, минимум пяти собственных ходов, оценки не
ниже −1.00 до конца и результата не поражение. Собственный ход с пересечением
−1.00 вниз считается потерей равенства. Успехи и проблемы имеют разные
критерии, поэтому их доли не обязательно складываются в 100%.

Серьёзные ошибки по стадиям — потери от 1.50 при исходной оценке от −2.00 до
+5.00. Их знаменатель — число собственных ходов в подходящих позициях стадии.
Для типов окончания знаменатель — число партий с подходящими позициями этого
типа, каждая партия считается один раз. Дебютные темы используют существующие
эвристические признаки решающих ошибок и число партий с дебютными ходами.
Изменение расстояния до мата не создаёт фиктивных потерь в пешках.

Сильная сторона требует минимум 10 партий с подходящими ситуациями, успехов
в 7 разных партиях и доли успешных случаев от 70%. Для слабости и тренировочного
приоритета нужны ошибки минимум в 3 разных партиях. Отсутствие ошибок не
превращается в положительный вывод. Приоритет учитывает частоту и сумму тяжести
ошибок: вес одного эпизода и вклад каждой партии ограничены 5 пешками, затем
сумма делится на число проанализированных партий и умножается на
`0.5 + 0.5 × доля проблемных случаев`. Подборки с перекрытием не менее 70%
от большего множества проблемных партий не дублируются; конкретные темы
предпочитаются общим дебютным и фазовым показателям.

Менее 20 подходящих партий дают предварительные выводы, 20–49 — умеренную
уверенность, от 50 — наблюдение на большой выборке. При покрытии анализом ниже
80% вывод всегда предварительный. Эти пороги не сравнивают игрока с рейтинговой
группой. Для динамики партийных показателей используются 95% интервалы Уилсона:
при пересечении убедительное изменение не заявляется. Показатели по ходам
показывают только изменение частоты, поскольку ходы одной партии зависимы.
Для «Всё время» и периода без обеих границ сравнение не вычисляется. Фильтр
результата сохраняется, а интерфейс поясняет ограниченность такой выборки.

Проверки резюме: `cd web && npm run test:summary` (Node.js 22.13+).
Тесты проверяют перспективу цвета, границы стадий и периодов, знаменатели,
реализацию после повторной потери преимущества, обработку мата, полноту анализа,
раздельные контроли и пороги уверенности.

Требуется Node.js 22.13 или новее. Нужная версия записана в `web/.nvmrc`.

```bash
cd web
nvm install
nvm use
npm install
npm run dev
```
